# 경쟁사 가격 대시보드 — 1단계 데이터 인벤토리

작성일 2026-09-09 · 대상 `sono-competitor-crawler`

---

## 1. 결론 먼저

**외장하드 64GB 아카이브는 대시보드에 거의 필요 없습니다.**

- 원본 `sono_competitor_prices_*.csv` 는 **누적본**이고, 하루 +20~25MB씩 append 되는 구조입니다.
- 누적이 3번 끊겼습니다(= epoch 3개). 각 epoch의 **마지막 파일 1개**가 그 구간 전체를 담습니다.
- epoch 종단본 3개가 **전부 로컬에 있습니다**. 아카이브 118개 파일은 그 3개의 중간 스냅샷입니다.
- 게다가 이미 `analytics/hotel_trends.csv` 가 **2026-04-15 ~ 09-08 전 기간(140일)** 을 정규화해 담고 있습니다.

| epoch | 기간 | 종단 파일 | 위치 | 크기 | 행수 |
|---|---|---|---|---|---|
| 0 | 04-15 ~ 04-19 | 일자별 5개 (비누적) | 로컬 | 3~13MB | — |
| 1 | 04-20 ~ 05-07 | `sono_competitor_prices_20260507.csv` | **로컬** | 311MB | 1,115,298 |
| 2 | 05-09 ~ 06-10 | `sono_competitor_prices_20260610.csv` | **로컬** | 729MB | 2,598,939 |
| 3 | 06-12 ~ 09-08 | `sono_competitor_prices_20260908.csv` | **로컬** | 1,879MB | 6,760,029 |

전 기간 raw 합계 **10,474,266 행**. 로컬 3파일 2.9GB만 읽으면 됩니다(아카이브 64GB 대비 1/22).

### 다만 100% 무손실은 아님 — 확인된 예외

누적본을 매일 새로 쓰는 과정에서 **소량의 행이 유실**됩니다. 실측:

| 비교 | 아카이브 | 로컬 종단본(동일 구간) | 차이 |
|---|---|---|---|
| epoch1 ~05-06 | 1,114,496 | 1,103,247 | **-11,249 (1.0%)** |
| epoch3 ~08-18 | 4,986,253 | 4,973,557 | **-12,696 (0.25%)** |

또한 중간 스냅샷끼리도 감소가 나타납니다(예: 05-01 743,910행 → 05-02 743,112행, 하루 지났는데 행이 줄어듦).
즉 완전 무손실을 원하면 118개 파일 전부를 읽어야 하고, 그 대가는 64GB I/O입니다.

**권고: 아카이브는 건드리지 않는다.** 유실분이 0.25~1% 수준이고, 대시보드는 일자·사업장·채널 **평균가 집계**를 보여주므로 이 정도 결손은 지표를 흔들지 않습니다. → 2단계 진행 전 사용자 확인 필요(아래 §6).

### 🔴 이슈 2 — 소노문 해운대 경쟁세트에 특급호텔 혼입 (사용자 기지 이슈, 실측 확인됨)

`analytics/insights/1_price_position.csv` 실측: **소노 평균 168,190원 vs 경쟁사 평균 561,745원 → 격차 -70%**

경쟁세트: 신라스테이 부산, L7 호텔 부산, 웨스틴 조선 부산, 파라다이스 호텔 부산, 그랜드 조선 부산.
웨스틴/그랜드조선/파라다이스는 체급이 다릅니다. 이대로 "소노 vs 경쟁사 격차"를 그리면 해운대는 영구 -70%로 고정되어 **인사이트가 아니라 노이즈**가 됩니다.

→ 대시보드 처리안: 경쟁사별 on/off 토글 + 기본값에서 특급 3사 제외, 또는 **체급 태그(특급/리조트) 부여 후 동급 비교 기본**.

## 6. 2단계 설계안 — 집계 산출물

### 소스 결정

```
analytics/hotel_trends.csv  (349MB, 140일, 정규화 완료)   ← 주 소스
analytics/golf_trends.csv   (7.4MB)                       ← 골프 탭(선택)
config.yaml                                               ← 권역/사업장/경쟁세트 정의
```

원본 CSV·외장 아카이브 **미사용**.

### 산출물 (docs/data/, 대시보드가 직접 fetch)

| 파일 | 내용 | 예상 크기 |
|---|---|---|
| `cd_meta.json` | 권역→사업장→경쟁사 트리, 채널 목록, 기간, 결측일, 품질 경고 플래그 | ~50KB |
| `cd_overview.json` | 일자×권역 롤업 (자사/경쟁사 평균가, 격차, 표본수) | ~200KB |
| `cd_prop/{property_id}.json` | 사업장별: 일자×채널×(자사/경쟁사별) price_avg/min/max, n, availability_rate | 각 0.5~2MB |
| `cd_gap.json` | 일자×사업장 소노-경쟁사 격차 추이 (채널 통합 + 채널별) | ~500KB |
| `cd_alerts.json` | 급등락 탐지 결과 (아래 규칙) | ~100KB |

사업장별 파일 분할이 핵심입니다. 전체를 한 파일로 만들면 20~30MB가 되어 초기 로딩이 무너집니다.
→ 대시보드는 `cd_meta` + `cd_overview` 만 먼저 로드하고, 사업장을 고르면 그때 `cd_prop/{id}.json` 을 lazy fetch.

### 급등락 탐지 규칙 (`insight_report.py` 로직 재사용·확장)

기존 `insight_report.py` 가 이미 5종 인사이트를 만들고 있어 그대로 승계합니다:

1. **가격 포지션** — 사업장별 소노 vs 경쟁사 평균격차·비쌌던비율
2. **경쟁사 급변** — 최근 7일 vs 직전 7일, ±3% 이상 (표본 30건 이상)
3. **채널 간 자사가 불일치 (rate parity)** — 같은 상품 채널 최고/최저 격차 5% 이상
4. **매진율** — availability_rate 로 수요 신호
5. **일자별 추이**

여기에 대시보드용으로 추가:

6. **일 단위 급등락** — 전일 대비 ±5% 또는 7일 이동중앙값 대비 ±10% 이탈 시 플래그. 표본 n<10 인 조합은 제외(노이즈 억제).
7. **격차 추세 전환** — 소노-경쟁사 격차의 7일 이동평균이 부호를 바꾸거나 10%p 이상 벌어진 시점.

### UI 축(3단계 예고)

```
[권역 ▾] [사업장 ▾] [채널 ▾] [기간 ▾]        ← 선택
────────────────────────────────────
요약 카드: 소노 평균가 / 경쟁사 평균가 / 격차 / 급등락 알림 n건
시계열 차트: 자사 vs 경쟁사 (채널별 라인 토글)
────────────────────────────────────
드릴다운: 경쟁사별 · 채널별 · 객실카테고리별 · 투숙일별
인사이트 패널: 위 1~7번
```

## 7. 확인이 필요한 결정 사항

1. **외장 아카이브 미사용 승인** — 0.25~1% 행 유실을 감수하고 로컬 소스만 쓸지. (권고: 예)
2. **소노문 해운대 특급호텔 처리** — 기본값에서 제외 / 체급 태그 분리 / 그대로 두기 중 선택.
3. **와이키키 하와이** — 제외 / "데이터 부족" 표기 중 선택.
4. **골프 데이터** — 이번 대시보드에 포함할지 (별도 탭) 여부.
